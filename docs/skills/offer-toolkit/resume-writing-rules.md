# Resume Writing Rules

来源：本仓库吸收的本地 `offer-toolkit-skill`，MIT 授权见同目录 `LICENSE.md`。以下规则是系统方法论，不携带源 skill 的示例履历事实。

## 结构化优先

所有入口先把简历内容整理成 `docs/RESUME_RENDER_CONTRACT.md` 定义的结构化数据，再让用户确认并渲染。换模板只改变版式，不重新解释事实。

核心顺序：

1. 基本信息和一句话定位。
2. 概要（可选，最多 3 到 4 行）。
3. 经历，按时间倒序。
4. 项目、教育、技能，根据应届、转行或资深身份调整顺序。
5. 证书、获奖、语言、发表、志愿等可选板块，没有内容就整块删除。

## Bullet 写法

每条经历尽量使用：

```text
强动词 + 具体动作 + 方法或范围 + 可验证结果
```

示例形态：`设计宿舍报修接口，支撑报修流程进入宿舍试用。`

不得把职责堆砌当作成果，不得把团队结果写成个人结果，不得把使用工具写成工具作者。数字只能来自用户陈述、权威文件或已验证证据；无法确认时保留 `[待确认]` 或使用用户确认过的定性影响。

## 追问顺序

采集或美化已有简历时，一次只问一个问题：

1. 时间、组织、角色。
2. 用户实际做的动作。
3. 协作对象和约束。
4. 结果、范围或变化。
5. 可验证证据。

用户不补充时保留事实缺口，不能生成看似完整的表述。

## 渲染检查

- 时间统一为 `YYYY-MM`，在职可用 `Present`。
- 最近经历放在最上方。
- 联系方式保持纯文本可选中的内容。
- 空板块整块删除。
- 一页优先；内容超出时先精简条目，不把字号降到模板可读下限以下。
- 所有用户文本进入 HTML 前必须转义。
- 模板是视觉系统，不是事实来源。
- 输出只写入本地 `output/resume/`，不自动打开浏览器、不上传。
