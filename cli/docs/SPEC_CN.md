# get-yourself-cli —— 专为中国大学生设计的求职/升学 CLI

> 对标：[career-ops](https://github.com/santifer/career-ops)（AI 驱动的多 Agent 求职系统，740+ 职位评估、100+ 定制简历、成功拿下理想岗位）
> 定位：把 career-ops 的架构哲学移植到中国校招场景，但**产品完全重做** —— 目标用户、领域模型、评分维度、数据文件全部面向中国大学生。
> 本文件是唯一权威规格（Spec），后续所有实现以本文件为准。

---

## 0. 对标分析：career-ops 抄什么、不抄什么

### 0.1 抄（架构哲学，全部复用）

| career-ops 原则 | 说明 | 我们的用法 |
|---|---|---|
| **Local-first** | 一切在本地跑，无账号、无服务端 | 完全沿用：学生数据绝不上云 |
| **AI-agnostic** | 逻辑写在 markdown 模式文件里，任何 AI CLI 都能跑 | 完全沿用：Claude Code / Qwen / Kimi / DeepSeek / Codex 都能用 |
| **Human-in-the-loop** | AI 评估和起草，人决定和点击，AI 永不自动提交 | 完全沿用，且对学生更重要 |
| **系统层/用户层分离** | `SYSTEM_PATHS` vs `USER_PATHS`，更新器永不动用户数据 | 完全沿用（Data Contract） |
| **文件即真相** | Markdown 文件是唯一权威，数据库只是派生索引 | 完全沿用：`data/*.md` + `reports/*.md` |
| **modes/*.md 是大脑** | 评分、评估、扫描、面试逻辑全在 prompt 文件 | 完全沿用 |
| **零 token 扫描器** | 公共 API 扫描职位，不消耗 LLM token | 沿用思路，但改中国信息源（见 5.2） |
| **报告+tracker 数据流** | scan → pipeline → evaluate → reports → applications | 完全沿用 |
| **市场模式机制** | `modes/zh/` 等按市场提供词汇和规则 | 我们直接以 `modes/` 为中文校招版，另留 `modes/job/` 社招扩展 |

### 0.2 不抄（career-ops 的假设不成立）

| career-ops 假设 | 为什么对大学生不成立 | 我们的替代 |
|---|---|---|
| 简历有多年工作经历、成果证明 | 学生简历是教育+实习+项目+竞赛+证书 | 学生简历模型（见 4.1） |
| 用户会谈薪（negotiation scripts） | 校招 offer 基本标准化，几乎无谈判空间 | **offer 对比**（城市/户口/平台/培养/加班）替代谈判 |
| 职级策略（leveling） | 校招没有职级 | 岗位方向（研发/产品/运营/算法/测试…）+ 培养体系评估 |
| 平台扫描 Greenhouse/Ashby/Lever | 中国校招不在这些平台 | 牛客/BOSS直聘/实习僧/宣讲会/学校就业网/双选会 |
| 求职是唯一路径 | 学生有就业/考研/保研/考公/出国五条路 | **多路径决策 + 双线作战管理** |
| 一次性短期冲刺 | 学生从大一就要开始积累 | **四年规划时间线**（能力积累日历） |
| 海外 ATS 优化 | 中国简历主要是人工筛选 + 学校就业系统 | 中文简历标准（一页、照片、绩点、排名） |

## 1. 产品定位

**一句话：一个跑在你本地 AI CLI 里的"校招作战指挥中心" + "毕业去向决策助手"。**

- 对**大三/大四（研二/研三）**：求职冲刺 —— 筛岗位、评估 offer、备面试、管进度、防诈骗。
- 对**大一/大二**：长期规划 —— 对照目标岗位做能力差距分析、竞赛/实习/项目积累时间线。
- 对**考研/考公党**：双线作战管理 —— 时间冲突提醒、调剂/上岸/求职的 Plan B 决策。
- 对**所有学生**：防骗 —— 培训贷、"包就业"、黑中介识别，是比 career-ops 的 Block G 更重要的功能。

### 1.1 核心用户画像

```
姓名：在校大学生（本科 3-4 年级为主，含研究生应届）
年龄：19-25
状态：秋招/春招/暑期实习求职中，或考研/考公/保研决策中
痛点：信息过载（海投海面）、简历无亮点、笔试面试没准备、
       offer 不会比、被黑中介/培训贷骗、时间管理混乱
付费意愿：几乎为零（免费、本地、用已有 AI CLI）
```

## 2. 核心概念：中国校招领域模型（必须内置的词汇与规则）

> 这些概念写进 `modes/_shared.md`（系统层），AI 评估任何岗位都必须理解。

| 概念 | 说明 |
|---|---|
| **应届生身份** | 毕业当年（+择业期 2 年），是最大的时间资产，过期作废 |
| **秋招 / 春招 / 暑期实习 / 日常实习** | 四个招聘季节，各有窗口期（秋招 9-11 月，春招 3-5 月，暑期实习提前一年 3-5 月投） |
| **网申 → 笔试 → 面试 → offer → 三方** | 校招标准流水线状态机 |
| **笔试** | 技术岗：算法题（牛客/LeetCode）+ 行测 + 性格测试（北森/智鼎） |
| **群面 / 技术面 / HR面** | 面试三阶段；群面是无领导小组讨论 |
| **三方协议** | 就业协议书，学校/学生/企业三方签，有违约条款（违约金） |
| **五险一金** | 养老保险/医疗/失业/工伤/生育 + 住房公积金；基数与比例是关键 |
| **年终奖** | 13 薪 / 14 薪 / 16 薪，大厂常见 |
| **户口 / 档案** | 落户政策（京沪难，新一线容易且有补贴）、档案去向 |
| **加班文化** | 996 / 大小周 / 弹性工作制 —— 校招必须问清 |
| **培养体系** | 管培生 / 校招生培养计划 / 导师制 —— 比薪资更重要的长期价值 |
| **公司类型** | 大厂 / 中厂 / 外企 / 国企央企 / 银行金融 / 事业单位 / 公务员 |
| **城市梯度** | 一线（北上广深）/ 新一线（杭蓉宁汉等）/ 二线；人才补贴、租房补贴 |
| **学历筛选** | 985 / 211 / 双一流 / 双非 —— 残酷但真实，评估时诚实标注 |
| **防骗红线** | 培训贷、黑中介、"包就业"、传销、收费内推、高薪兼职骗局 |

## 5. 技术架构

### 5.1 技术栈（对标 career-ops）

| 层 | 技术 | 理由 |
|---|---|---|
| 大脑 | `modes/*.md` markdown 模式文件 | AI 无关，任何 CLI 可跑 |
| 工具脚本 | Node.js `.mjs`（零/低 token） | 扫描、文件操作、PDF 不走 LLM |
| 简历 PDF | Playwright + HTML 模板 | 中文排版友好、可精确控制 A4 一页 |
| 数据 | Markdown + YAML + TSV | 可 git diff、可读、可迁移 |
| TUI（可选） | Go + Bubble Tea | 进度看板，后续迭代 |
| 入口 | AGENTS.md + 多 CLI 包装（CLAUDE.md/CODEX.md/QWEN.md/KIMI.md） | agent-skill-standard |
| 免费运行 | 支持 DeepSeek / Qwen / Kimi 免费档 + Ollama 本地模型 | 学生零预算 |

### 5.2 扫描器：中国校招信息源（零 token 优先）

| 信息源 | 方式 | 说明 |
|---|---|---|
| **公司校招官网** | 公司 careers 页面 + 校招子站（如 `campus.xxx.com`） | 秋招/春招官方信息，最可信 |
| **牛客网** | 笔试真题、面经、校招日历 | 笔试刷题 + 面经，可公开抓取 |
| **学校就业信息网** | 宣讲会/双选会公告 | 每个学校一个，学生自己配置 |
| **BOSS直聘/实习僧** | 需登录 → 划入"手动输入"类（同 career-ops 对 auth 站的处理：插件层，不进核心） | 学生粘贴 URL/截图即可 |
| **微信群/就业群** | 手动粘贴 | 学生日常渠道 |
| **企业宣讲会** | 日历导入（.ics） | 宣讲会时间冲突检测 |

### 5.3 状态机（tracker 核心）

```
网申(Applied) → 笔试(OnlineTest) → 一面(Interview1) → 二面(Interview2) → HR面(HR)
  → Offer → 三方(Signed) → 入职(Joined)   [终态：Hired]
             ↘ 放弃(Declined) / 拒信(Rejected) / 失效(Closed) / 跳过(SKIP)
```

**双线作战状态（考研党）：** `备考中 → 初试 → 复试/调剂 → 上岸(GraduateSchool)` 或 `落榜 → 转向春招/考公`。`exam-plan.md` 与 `applications.md` 共享一个日历视图，检测冲突（如 12 月考研 vs 秋招终面）。

## 6. 评分系统设计（对标 career-ops 的 1-5 五维评分，但维度换血）

> 综合分 1-5；≥4.0 才建议投递；3.5-3.9 仅特殊理由；<3.5 不建议（沿用 career-ops 原则）。

### 6.1 校招岗位评估维度（eval mode）

| 维度 | 衡量内容 | 权重 |
|---|---|---|
| A. 岗位匹配度 | 岗位要求 vs 学生简历（技能/项目/实习） | 25% |
| B. 方向契合度 | 岗位 vs `_profile.md` 目标方向（如"后端开发"） | 15% |
| C. 平台与培养 | 公司口碑、培养体系、导师制、转正率、应届生重视度 | 20% |
| D. 综合待遇 | 薪资（base+年终）、五险一金比例、加班强度、补贴 | 20% |
| E. 城市与户口 | 城市梯度、落户难度、生活成本、人才补贴 | 10% |
| F. 红线扣分 | 996 明文、无培养、外包、资质存疑、学历歧视显性化 | -10% |
| **G. 真实性（独立）** | 防骗核查：培训贷/收费/包就业/黑中介/传销信号 → **不参与总分，但 3 级警示** | 独立 |

**G 级警示**（比 career-ops 更强，因为学生更易被骗）：
- 🔴 **立即拒绝**：入职前收费（培训费/服装费/押金）、"贷款培训包就业"、无明确岗位只说"高薪"、需发展下线
- 🟡 **重点核查**：中介代招、岗位描述与实际不符、HR 话术过度热情、要求立即签约
- 🟢 正常

### 6.2 offer 对比维度（compare mode）

| 维度 | 说明 |
|---|---|
| 总包计算 | base×月数 + 年终 + 补贴 + 五险一金实际到手（**税前/税后换算**） |
| 户口 | 能否落户、落户成本 |
| 培养 | 管培/导师/轮岗/晋升通道 |
| 加班 | 日均工时、大小周、加班费/调休 |
| 城市成本 | 房租/通勤/生活成本 vs 薪资 |
| 稳定性 | 公司现金流、裁员风险、试用期 |

## 8. 与 career-ops 的关系（决策：fork vs 新建）

**建议：新建独立仓库（可先 fork 参考），不复用其代码。**

理由（这正是之前那篇重构文章的教训）：
1. career-ops 的 123 个 .mjs 脚本 80% 服务于社招假设（谈判、职级、ATS、LinkedIn）—— 硬继承 = 一堆死代码。
2. 领域模型完全不同（应届生身份、三方、双线作战）—— 评分和模式文件全要重写。
3. **保留其架构哲学和模式文件结构**（这正是它最值钱的部分），用"规格移植"而非"代码复制"。
4. 名字、品牌、社区完全独立（对标 MIT 许可，可以合法借鉴思路）。

## 9. 附加：与 Get Yourself 的协同（可选）

用户已有 `Get Yourself`（大学生成长记录平台：成长时间线/AI 教练/能力评估）。get-yourself-cli 的 `cv.md` 能力证据可以直接从 Get Yourself 的能力评估结果导入（"我能证明什么" → 简历素材），形成闭环：

```
Get Yourself（记录成长+提炼能力证据）→ get-yourself-cli（求职/升学作战）
```

此为后续整合点，Step 0-8 不依赖它。
