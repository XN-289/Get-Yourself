# 模式: scan —— 校招信息源扫描

扫描校招信息源，把新岗位收集到 `data/pipeline.md`。

## 信息源（中国校招）

| 信息源 | 方式 | 说明 |
|--------|------|------|
| **公司校招官网** | `providers/` 模块（零 token API） | 如 `talent.alibaba.com`、`careers.tencent.com`、美团校招站 |
| **学校就业信息网** | 手动粘贴（用户提供 URL/内容） | 宣讲会/双选会公告，各校不同 |
| **牛客网** | 面经/笔试/校招日历 | 用户手动搜索或粘贴 |
| **BOSS直聘/实习僧** | 需登录 → 手动输入 | 用户粘贴 URL/岗位文本即可 |
| **宣讲会日历** | 手动添加 | 企业来校宣讲，现场投递机会 |

**auth 类平台（BOSS/实习僧等）不在核心扫描器内**（需要登录），用户手动粘贴进 pipeline 即可。

## 执行

1. 读 `portals.yml`（用户配置的目标公司/平台/关键词）
2. 对每个入口，调用对应 `providers/` 模块（零 token，不消耗 LLM）
3. 新岗位（按 URL 去重）追加到 `data/pipeline.md`
4. 已存在/已评估的自动跳过

## pipeline.md 格式

```markdown
# 待评估岗位

- [ ] 公司 | 岗位 | 城市 | 来源 | 日期
- [ ] 腾讯 | 后端开发工程师 | 深圳 | 校招官网 | 2026-09-10
```

处理完一条：`- [x] ~~公司 | 岗位~~` 标记完成。

## 去重与信任

- URL 规范化去重（去 tracking 参数）
- 可疑来源标记（防骗信号）不自动过滤，但标注

## 完成

报告扫描结果：
- 新增 N 条
- 重复跳过 M 条
- 来源统计

然后建议用户运行 `pipeline` 模式处理 inbox 或直接粘贴某个岗位评估。
