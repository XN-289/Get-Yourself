# 模式: compare —— offer 对比

当用户有多个 offer（或 offer vs 继续面试）时，生成结构化对比。

## 对比维度（校招版）

| 维度 | 内容 |
|------|------|
| **总包（年）** | base×月数 + 年终 + 补贴（标注税前） |
| **到手估算** | 扣五险一金个人部分 + 个税后的月到手（粗略，标注为估算） |
| **五险一金** | 基数（是否全额）、公积金比例（5%-12%） |
| **户口** | 能否落户、难度、成本 |
| **培养** | 管培/导师/轮岗/晋升通道 |
| **加班** | 日均工时、大小周、加班费/调休 |
| **城市成本** | 房租/通勤/生活成本 vs 薪资 |
| **稳定性** | 公司现金流、近期新闻、裁员风险 |
| **平台价值** | 跳槽认可度、业务前景、个人成长 |

## 建议纪律

- AI 给**分析**，不给绝对命令。列出每个维度的优劣、权衡点、适合什么性格/目标的人
- 尊重用户红线（`_profile.md` 里的"不去 996"等）
- 如果关键信息（五险一金基数/公积金比例）未知，标注"信息不足，需向 HR 确认"，并给出**该问 HR 的问题清单**
- 三方协议违约金、offer 有效期（口头 offer 有效期）等时间压力也要提示

## 该问 HR 的问题清单（默认附送）

1. 五险一金基数？公积金比例？
2. 年终奖几个月？发几个月基数？
3. 加班强度？大小周？加班费/调休？
4. 户口能解决吗？条件？
5. 培养计划/导师制？
6. offer 有效期多久？三方违约金多少？
